## 2. V2.4 Architectural Specification

V2.4 implements a dual-layer defence: **Token-Level State Machine (`ReentryGuardV2_4`)** combined with **Token Risk Budgeting (`TokenExposureManagerV2_4`)**.

```
                        +-----------------------+
                        |     [ELIGIBLE]        |<---------------------+
                        +-----------------------+                      |
                                    |                                  |
                              (Buy Signal)                             |
                                    v                                  |
                        +-----------------------+                      |
                        |      [ENTERED]        |                      |
                        +-----------------------+                      |
                                    |                                  |
                             (Position Exit)                           |
                                    v                                  |
                        +-----------------------+                      |
                        |       [EXITED]        |                      |
                        +-----------------------+                      |
                                    |                                  |
                     (Check Token Risk Budget)                         |
                   /                            \                      |
           (Budget Breached)             (Budget OK)                   |
                  v                               v                    |
       +--------------------+          +--------------------+          |
       |   [TOKEN_LOCKED]   |          |    [COOLDOWN]      |          |
       |  (Permanent Stop)  |          +--------------------+          |
       +--------------------+                     |                    |
                                         (Cooldown Expired)            |
                                                  v                    |
                                       +--------------------+          |
                                       |    [REARMING]      |          |
                                       +--------------------+          |
                                                  |                    |
                                        (Thesis Reset Check)           |
                                        /                  \           |
                               (Reset Confirmed)        (Reset Failed) |
                                      |                        |       |
                                      +------------------------)-------+
                                                               v
                                                      [Return to COOLDOWN]
```

### 2.1 State Machine Mechanics
1. **`ELIGIBLE`**: Token is free to enter when standard strategy signals trigger.
2. **`ENTERED`**: Active position open. Re-entry strictly blocked.
3. **`EXITED`**: Position closed. Exit reason, realized P&L, and timestamp are recorded.
4. **`COOLDOWN`**: Dynamic time-based lockout active.
5. **`REARMING`**: Cooldown elapsed. Token must demonstrate fresh, independent order flow before re-entering.
6. **`TOKEN_LOCKED`**: Token has exhausted its risk budget and is permanently barred from further trading.

### 2.2 Mathematical Formulations

#### Dynamic Cooldown Duration:
$$T_{\text{cooldown}} = T_{\text{base}}(\text{Reason}) \times (1.5)^{\max(0, N_{\text{consecutive\_losses}} - 1)}$$

| Exit Reason | Base Cooldown ($T_{\text{base}}$) | Rationale |
|---|---|---|
| `HARD_SAFETY` / `EMERGENCY` | **60s** | Prevent catching falling knives after severe rug/dump |
| `FLOW_FAILURE` / `LIQUIDITY_FAILURE` | **30s** | Allow order book recovery after liquidity drain |
| `BREAKEVEN_PROTECTION` | **15s** | Short pause following scratch trade |
| `TRAILING_EXIT` (Runner) | **5s** (0s debounce) | Preserve legitimate second-leg runner continuations |
| `DEFAULT` | **30s** | Standard protection |

#### Thesis Reset Condition:
A token in `REARMING` transitions to `ELIGIBLE` if and only if:
$$\text{NetFlow}_{30s} > 0 \quad \land \quad \text{BuyAccel}_{30s} > 0 \quad \land \quad \text{DistRisk}_{10s} < 75 \quad \land \quad \text{CoordRisk}_{10s} < 80$$
If any condition fails, the token is returned to `COOLDOWN`.

#### Token Risk Budget Parameters:
- **Max Consecutive Losses**: **2** (Strict lockout after 2 back-to-back losses)
- **Max Lifetime Entries**: **3** (Prevents endless churning)
- **Max Cumulative Exposure**: **0.30 SOL**
- **Max Cumulative Realized Loss**: **0.05 SOL**
